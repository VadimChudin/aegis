# AEGIS — подключённый событийный цикл Paper

## Что подключено в коде
База56b4144; изменение существующего observer, а не ещё один неиспользуемый модуль. Новая политика выключена по умолчанию и разрешена только для Paper.

- sample_loop пишет реально полученные MarketSample с тиками и текущим DOM в source-tape.jsonl каждые30 секунд; source-bound буфер хранит выборку котировки/DOM. Это не полный исторический поток тиков. Исторический стакан не придумывается.
- Окно2/3/10часов: по умолчанию требуется накопленная выборка до границы окна и промежутки не более45секунд. Пробелы и полнота данных обозначены отдельно. Автоматической загрузки всей истории MT5 здесь нет.
- Существующая локальная модель предлагает long/short по стратегии; для такого кандидата добавляется отдельный настоящий Runtime::score. JSON score/horizon/identity проверяется, score строго>8 допускает зарезервированный облачный запрос. score8и ниже, неправильный ответ и устаревшие данные не допускают новый запрос/вход.
- Детальный облачный запрос содержит исходный snapshot/local_proposal, а также event_review: score, прогноз горизонта и агрегированный срез телеметрии. Эти данные сохраняются в журнал. После локальной оценки повторно проверяются отмена/epoch перед резервированием и отправкой.
- wait/close/reduce/stop в новом Paper-режиме обходят порог нового входа и облачный запрос; детерминированные проверки действий остаются. Автоматический mark/SL/TP выполняется до операций записи телеметрии.
- Облачные резервирования записываются/fsync до dispatch: лимит запросов/час, дедупликация и консервативный учёт неоднозначной попытки. Это не точный денежный/token budget.
- Принятый Paper-вход связываетeventID сpositionID. Journal reconcile обрабатывает автоматические/модельные/ручные закрытия и replay после restart. Частичный выход не снимает pin до полного закрытия.
- В sample_loop подключён catchup завершённых UTC-недель (максимум52) и JSON-сводки с рекомендациями. Автоматического изменения риска/настроек нет.

Включениеevent_paper_enabled=false по умолчанию; окноevent_window_hours=2 (2/3/10); event_cloud_calls_per_hour=5 (1..60); event_cooldown_seconds=300 (30..86400). Дополнительное backend-разрешение частичной выборкиevent_allow_partial_coverage=false, в UI не предлагается. В Money новая политика отклоняется. Добавлены EN/RU пояснения параметров; остальные разрешения и session-arm не ослаблены.

## Осталось — не считать полностью автономной системой
1. Permanent finalized-event archive/full-ledger weekly statistics ещё не реализованы: bounded telemetry может вытеснить finalized events, weekly явно сообщает retained-only/incomplete. source-tape hardcap8MiB без безопасной rotation/archive: при заполнении новые события блокируются; требуется обслуживание.
2. Итоговый P/L по сделке с несколькими partial reductions не агрегирован полностью; последнее закрытие не является всей суммой. До реализации агрегации такие итоги не следует использовать для подбора стратегии.
3. Недельные рекомендации — базовые policy flags, а не обученная оценка/проверенные версии параметров. Auto-tuning и автоприменение не включены.
4. Срез для score состоит из агрегированной sampled price/DOM availability истории; raw ticks хранятся отдельно. Полная историческая tick microstructure и динамический доступ модели к фрагментам ещё не реализованы.
5. Реальная CPUQwen ранее превышала рабочие deadlines; новый цикл может безопасно отклонять её из-за freshness. Replay не подтверждает GPU/CPU latency или доходность.
6. Новый установщик не собран. Native кнопки, WindowMT5demо и длительный soak остаются необходимыми перед включением политики.

Изменения публикуются в существующийPR#55, main и Money не включаются автоматически.
